# Local Laravel fixture for iPhone verification

This test server runs the real Laravel routes, middleware, policies, controllers, services, SQLite schema, image processing, and Sanctum mobile-token checks. It gives native account, administration, Places, directories, TierList, Board, and Guess Who tests a writable backend without touching the live site.

Run these commands from the repository root:

```sh
node ios-app/scripts/local-fixture.mjs setup
node ios-app/scripts/local-fixture.mjs start
node ios-app/scripts/local-fixture.mjs check
```

`setup` replaces the isolated fixture database, media, cache, and sessions, and rotates its mobile tokens and session gate. Stop the fixture first. `start` runs in the background and prints process IDs and loopback ports. `check` runs the HTTP, upload/moderation, AssetManager storage, real two-client WSS, and native-client decoder checks. It clears only the fixture's cache between scenarios so earlier scenarios don't consume the next scenario's rate limits. Application requests still pass through their normal throttles.

The native API origin is `https://127.0.0.1:9443`. PHP listens on `127.0.0.1:9017`, Reverb on `127.0.0.1:9018`, and a local S3 protocol fixture on `127.0.0.1:9019`. The HTTPS proxy forwards WebSocket upgrades to Reverb on the same port 9443. The original root view advertises this local WSS host, port, and public app key. No production SDK settings need to change.

`node ios-app/scripts/local-fixture.mjs restart-proxy` reloads only the verified local proxy between native cohorts. It adopts the exact existing PHP and Reverb processes after checking their owner and script paths. The TLS and S3 listeners restart together; stored objects, SQLite, cache and fixture accounts are preserved. Pending simulated-provider state lives in proxy memory, so complete browser tests before this operation. The session handler reads `access.json` on each request; a private atomic gate rotation does not require a PHP restart.

All runtime files live under ignored `ios-app/.expo/local-fixture/`:

Trust only `tls/ca.pem` in the test simulator, using `simctl keychain <simulator-id> add-root-cert <absolute-ca-path>`. Don't add the CA to macOS trust, a physical phone, or a shipping app. The generated certificates expire after 30 days. If they expire, stop the server and run `node ios-app/scripts/local-fixture.mjs tls`, restart it, and import the new CA into the simulator.

Native tests select a local fixture user through their test-only launch or Keychain setup. `GET /__native_fixture/session?user=member` returns `{origin, token}` only when its `X-Native-Fixture-Key` header matches `access.json`'s `key`. Its closed alias map is `member`, `other`, `admin`, `banned`, and disposable `avatar`. The Node proxy requires loopback and an absent Origin header, and sends `no-store`. This endpoint doesn't exist in Laravel or production. Pass the header gate through test-only process launch configuration, never `EXPO_PUBLIC` or bundled source.

Each gated request creates a fresh real Sanctum mobile token and updates only that user's token in the ignored fixture configuration. A revoked token stays revoked, and the next test launch can obtain a new usable token. The original API still rejects banned users and enforces their mutation policies. A soft-deleted seeded account returns 410 rather than being restored or recreated. Reset the fixture when the account-deletion scenario is finished.

Use the account provider's origin-scoped SecureStore key for the selected origin. The canonical production key remains `zone.syrian.ios.access-token`. Credentials must stay out of app bundles and screenshots. The normal native account provider restores the token and obtains the server-owned effective permissions through `/api/v1/user`. This doesn't test Google's real upstream behavior, which requires the website's configured Google provider credentials and HTTPS callback.

It verifies the test gate, loopback origin, testing environment, and isolated database before changing only the existing eligible admin 103's password. ## Simulated browser provider

`node ios-app/scripts/local-fixture.mjs check-google` drives real HTTPS requests through the source native Google broker, browser session cookies, installed Socialite state validation, the source callback, SQLite DatabaseCache grant locks, PKCE exchange, authenticated user lookup, and logout. The provider transport is simulated entirely inside the test proxy. This proves the application's browser handoff protocol, not Google verification or real Google integration.

The original native start route is `/auth/google/native`. Only the fixture bootstrap configures a local GoogleProvider subclass. It inherits Socialite's redirect, state validation, token-field construction, and user mapping. Its external URLs and HTTP client are confined to the local HTTPS provider. The original upstream callback stays `/auth/google/callback`, and the actual broker returns `zone.syrian.ios:/oauth/google` to the app. No fake token response is sent directly to the app. All app sessions come from the original broker and its fresh-user policies.

The browser sees heading `Local provider fixture`, an explicit statement that no Google service or verification is involved, approve button `Continue as local member 101`, and cancel button `Cancel local sign-in`. Only the existing synthetic member 101 with email `member@native-fixture.invalid` can be emitted. The provider never selects an administrator or another identity. Usable upstream consent/state lasts 120 seconds, authorization codes last 60 seconds, and userinfo access tokens last 30 seconds. Each consent nonce, upstream code, and access token is one-use. A non-usable state replay marker stays for the broker context's full 600-second lifetime, so an old authorization URL can't obtain another consent after its shorter consent TTL. Pending entries are bounded and exist only in the local proxy's memory.

Provider endpoints exist only under `/__native_fixture/google/` in the Node proxy. They require TLS, exact loopback host and port, a loopback caller, and the testing configuration. Nonlocal Origin headers are refused. The installed driver verifies the same testing environment, isolated database, and HTTPS request origin before transport. Framework HTTP requests remain blocked, and the simulated client's Guzzle handler rejects every destination outside the two exact local token/userinfo endpoints. The fixture's default cache is DatabaseCache so the source broker's real lock and atomic consumption behavior is exercised.

The consent HTML alone uses `Referrer-Policy: strict-origin`, so a browser's non-CORS form POST retains its tuple Origin while referrers expose no path or query. Other provider responses and the production broker's callback headers keep `no-referrer`. Null and foreign form origins remain refused. This follows the [Fetch Standard's request-Origin algorithm](https://fetch.spec.whatwg.org/#append-a-request-origin-header). Actual native Safari metadata after this change records the exact local tuple Origin and reaches the callback's local token and userinfo requests. The initial rejection's Origin wasn't captured. Diagnostic JSONL records contain only method, path without query, sanitized Origin, Host, TLS flag, and remote IP.

The consent document's CSP permits `form-action 'self' zone.syrian.ios:`. [WebKit checks redirected form targets](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/loader/FrameLoader.cpp), so `'self'` alone blocks the final custom-scheme redirect even after the source broker issues its grant. The [CSP grammar](https://www.w3.org/TR/CSP3/#source-list-syntax) cannot express an exact path for a hostless custom URL. The one named scheme is the narrow valid policy expression; the production broker and native parser still enforce the exact `zone.syrian.ios:/oauth/google` callback and its state. No foreign HTTPS origin or other scheme is allowed. An actual native rerun must verify the OS return. The earlier failed native run had exact same-origin consent, successful local token/userinfo transport, and a fresh unconsumed broker grant, which localizes that failure after broker issuance.

The headless proof checks active source Laravel CSRF rejection, foreign-origin refusal, wrong upstream state, missing browser cookies, reused consent, upstream code/state replay, wrong PKCE verifier/client state, one-use broker redemption, absent browser-account login, real token authentication/revocation, and provider cancellation. Native ASWebAuthenticationSession and OS scheme handoff still require the separate iPhone UI cohort. Don't run the broad `check` command while a browser cohort is pending, because that older general self-check clears the isolated cache between scenarios and would remove pending broker grants. `check-google` doesn't clear any cache or alter existing fixture tokens.

## Isolation and limits

The bootstrap ignores the repository's `.env`, forces its own SQLite connection and storage path, and refuses a different database. Service processes inherit only basic shell environment variables. Their configuration and package caches stay inside the fixture directory.

Laravel HTTP requests cannot reach unstubbed services. PHP remote stream reads are disabled. Mail, notifications, and queued jobs use test fakes. Broadcasts reach only local Reverb. The router refuses legacy real Google login and exchange routes with 503, while the three source native-broker routes can use the explicitly simulated test provider. Product authentication, permission checks, and Laravel routes remain unchanged. Public Home and private Inertia pages use the original root template with a test-only equivalent of Laravel's `withoutVite` helper, so no Vite server or asset manifest is needed.

AssetManager hard-codes the R2 disk and directly creates an AWS client. The fixture overrides that disk's configuration to use dummy signing values and the loopback S3 endpoint. Original controllers and AWS/Flysystem clients still execute. The local protocol supports small object upload, list/pagination, read, and delete. It preserves bytes and stores files under the ignored runtime directory. Multipart S3 uploads return 501, and real Cloudflare R2 availability isn't covered. Public HTTPS asset paths accept only GET and HEAD.

The checks establish backend behavior, HTTPS trust, the native transport/decoder contract, and real WSS fan-out. They don't establish an observed iPhone interaction, the native Pusher SDK lifecycle, real Google login, physical-device reachability, or external feed availability. The test origin is loopback, so a physical iPhone can't use it.

Check service status or stop every local process with:

```sh
node ios-app/scripts/local-fixture.mjs status
node ios-app/scripts/local-fixture.mjs stop
```

Stop verifies the recorded proxy process belongs to this script and waits for it to stop. Its shutdown also stops its PHP and Reverb children. Keep the ignored directory while native tests need its database and tokens, or remove it after stopping the services. No command pushes, publishes, deploys, changes system trust, or contacts production.
