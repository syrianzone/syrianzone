# Native Google sign-in handoff

Status: accepted for local implementation after root and independent protocol review. Server deployment and real Google end-to-end success are pending. No production credentials or Google Cloud changes were used for this work.

The existing Google confidential web client authenticates through its registered HTTPS callback. Syrian Zone acts as the app's identity broker. Google client secrets remain on the server; native receives only a short-lived code before the normal mobile token exchange. The existing ordinary web login and Flutter token routes retain their behavior.

## Wire contract

1. Native generates independent verifier and client state from 32 random bytes each through Expo Crypto. Both use lowercase hexadecimal encoding, so the verifier has 64 RFC7636-unreserved characters and 256 bits of entropy. Native computes `BASE64URL(SHA256(verifier))`, without padding. Neither verifier nor state is persisted.
2. `ASWebAuthenticationSession` opens the configured HTTPS site's `GET /auth/google/native?code_challenge=<43 canonical base64url characters>&code_challenge_method=S256&state=<64 lowercase hex characters>`. No client secret, bearer, arbitrary return URI or Google iOS client ID is sent.
3. Server binds this attempt to the browser session and its independently generated Socialite upstream state. Start context expires after 10 minutes. A native marker is tied to that exact upstream state, including an expired marker's fail-closed handling. A stale or interleaved callback cannot consume a newer attempt or fall through to web login.
4. The existing Google callback uses Socialite validation, verifies native Google email claims, resolves the source account policy and checks bans. A native success creates a 32-byte random one-use handoff code, stores only its hash and binding metadata, and redirects to exactly `zone.syrian.ios:/oauth/google?code=<43 canonical base64url characters>&state=<original native state>`. The code expires after 60 seconds. The native branch never calls web `Auth::login`.
5. Native checks the entire fixed callback prefix, rejects raw controls/whitespace before URL normalization, rejects every fragment, duplicate or unknown parameter, and matches the original client state. The only error variants are `auth_failed`, `auth_expired`, `banned`, and `unverified_email`, with the trusted original native state. Code and error are mutually exclusive. No callback can carry a bearer or arbitrary error text.
6. Credential-free `POST /api/v1/auth/google/native/token` sends JSON `{code,code_verifier,state,device_name}` through the existing configured API client. It attaches neither a prior bearer nor browser cookies. Server validates the grant/state/S256/absolute expiry under a configured shared Database or Redis lock, atomically adds a consumed marker for the code hash with a 120-second lifetime, and requires grant removal before entering the fresh user-row lock/token transaction. It rechecks current account/provider/expiry and returns the existing `{token,token_type:'Bearer',expires_at,user}` mobile DTO. Responses use `no-store, private`.
7. Native reuses common validated session adoption and origin-scoped Keychain storage. Provider unmount aborts its owned browser/exchange. Keychain reads, replacements and removals share a queue for that origin's token key. A newer generation supersedes pending work. If cancellation or a stale epoch arrives during a Keychain write, the previous value is restored before the queue permits a bootstrap read or newer write. API and React session adoption run synchronously at the guarded commit point. An exchange is never retried automatically because the code is one-use.

## Decisions and threats

- The dedicated `zone.syrian.ios` scheme follows controlled reverse-domain naming. Existing `syrianzone` navigation remains separate. A claimed HTTPS callback is preferable if associated-domain deployment becomes available, but requires its own rollout.
- App-generated S256 prevents an app that merely intercepts a code from redeeming it. A custom scheme and PKCE do not establish the caller's binary identity. User initiation, system browser context and strict state validation still matter.
- Native client state and upstream Google state are separate. Socialite consumes its session state during `user()`, so server classification must snapshot and bind the native attempt before that call. Never use a loose `native=true` flag.
- Ordinary browser routing and Flutter token exchange remain separate. The new mobile branch requires verified email because the existing mobile Google-token endpoint already does. Shared account resolution now locks and rereads the current account, preserving current role/name/password/custom avatar rather than replaying a stale snapshot. Configured-email role defaults apply at creation only. Root explicitly authorized this shared concurrency correction after its demotion/avatar race reproductions. Signup, soft-delete restoration and ban handling remain source-authoritative.
- The atomic consumed marker is the replay proof even if a lock lease expires or DatabaseStore reports successful removal without deleting a stale row. The marker survives later database failure. Grant removal or fresh-account validation failure cannot mint a token. A lost successful response may require a fresh browser login; it does not justify automatic replay.
- The app API origin is configured independently of callback input. Server return URIs are fixed. No callback code, verifier, state or bearer belongs in analytics, public logs, screenshots or browser content.
- The credential queue protects cancellation, provider remount and completed rollback within a live process. If Keychain rollback fails, reads remain blocked until repair succeeds. The previous value and repair marker exist only in memory. Process death before rollback settles, or during an OS Keychain failure, is outside this guarantee. This is not crash-atomic authentication, and no credential backup is written to a file or SQLite.

## Evidence and remaining proof

Eleven native broker unit cases pass 65 assertions for request secrecy, independent randomness, exact callback/scheme registration, canonical base64url, duplicate and unknown parameters, raw-control normalization, wrong state, allowed provider errors, cancel/dismiss, abort with late callback, stale epochs and non-retried exchange failure. The real API client test checks credential-free exchange without altering an existing session. These use deterministic synthetic values and injected transports. Whole native TypeScript and targeted ESLint pass.

Nine credential transaction cases pass 38 assertions. Delayed native-storage fakes prove that canceled writes cannot be restored by queued bootstrap or a subsequent helper after rollback, that an older write or logout cannot erase a newer valid session, that failed partial writes preserve the prior value, and that a failed repair blocks reads until recovery. The complete focused native auth cohort passes 25 cases and 116 assertions, independently rerun by a blind reviewer. Removing post-write cancellation rollback in an isolated temporary copy causes four behavior tests to fail. Root and the independent reviewer checked every production token access and native sign-out/deletion clearing without finding a blocker under the live-process contract. Raw fixture token writes occur only before App mounts. These are deterministic storage and lifecycle models, not an OS Keychain failure or process-kill test.

Root's recorded integrated-origin-controls source checkpoint passes 530 cases and 5,607 assertions across 143 files, TypeScript and ESLint. Later fixture changes require their own checks. Frozen dependency installation and native dependency installation also pass. Root confirmed both callback schemes in the generated and built app's Info.plist. Actual native browser cancellation keeps the local fixture signed out. After the fixture consent-page policy correction, account-native06 passed synthetic consent, native browser return, one-use exchange, account adoption, dashboard access and logout. The overall eight-case cohort had five passes (including one cleanup case) and three failures; it was not a complete native green result. Account-native07 subsequently passed campaign administration and Home popup geometry. Account-password-native16 later passed eligible-administrator login/adoption/dashboard/logout, native wrong-password rejection and native 429 countdown/disabled controls after bounded local HTTP throttle setup. Cleanup and product restoration passed. This does not establish six consecutive native attempts or deep-link panel expansion. Real Google success is unverified and requires server deployment. Local fixture authentication does not establish real Google success. No deployment is authorized by this document.

Independent backend review completed after the resolver/current-read and late-attempt expiry corrections. The current focused broker/resolver suite passes 56 cases and 563 assertions. Review checked installed Socialite state consumption, DatabaseStore's unconditional-success removal semantics, atomic Database/Redis claims, callback boundaries, fresh account/provider checks and existing web/Flutter routes. The concurrency tests stage controlled interleavings and unique-email fallback on SQLite. They do not establish parallel MySQL production behavior; the current-read corrections are additionally supported by installed Laravel code and official MySQL isolation documentation.
